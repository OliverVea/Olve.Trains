# Unified Always-Instanced Renderer

## Motivation

The engine currently has two separate rendering managers (`RenderingManager2D`, `RenderingManager3D`) with three rendering paths:
1. **2D instanced** — per-instance VAO/VBO, depth-sorted, no depth test
2. **3D uniform-per-draw** — shared geometry, per-instance world matrix as uniform, N draw calls
3. **3D GPU-instanced** — shared geometry, per-instance data in vertex buffer with divisor=1, 1 draw call

These can be unified into a single renderer where instance data is opaque to the engine. The shader defines what per-instance data means (world matrix, Hermite control points, 2D rect transform, etc.), and the engine just manages two buffers per draw group: geometry (divisor=0) and instances (divisor=1).

## Target API

```csharp
// Register reusable geometry (uploaded once)
GeometryId geoId = renderer.RegisterGeometry<TVertex>(vertices, indices);

// Create an instance group bound to geometry + shader
GroupId groupId = renderer.RegisterGroup<TInstance>(geoId, shaderId);

// Update all instances for a group (rebuilds instance buffer)
renderer.SetInstances<TInstance>(groupId, instanceSpan);

// Render all groups using this shader (1 draw call per group)
renderer.Render(shader);
```

- `TVertex : IVertexData` — generated from non-`@instanced` shader inputs
- `TInstance : IInstanceData` — generated from `@instanced` shader inputs
- Both types are source-generated by the asset pipeline from GLSL

## Steps

### Step 1: Asset pipeline generates `Vertex` for all shaders

The pipeline already generates `Instance` from `@instanced` attributes and `Vertex` from non-instanced attributes, but only when those attribute categories exist. Some shaders (like `track.vert`) have both, but the `Vertex` wasn't being generated. Others (like `building.vert`) only have non-instanced attributes and get `Vertex` but no `Instance`.

**Changes:**
- Update Scriban templates to always emit `Vertex` from non-`@instanced` `layout(location=N) in` declarations
- Verify all shaders produce both types after running the pipeline
- Delete `TrackTemplateMeshService.TrackVertex` — use `Track.Vertex` instead

**Validation:** Asset pipeline compiles, project builds, no behavior change.

### Step 2: Migrate shaders to always-instanced

Move per-instance uniforms to `@instanced` vertex attributes. Each shader gets at least one `@instanced` input.

**Shader migrations:**
- `building.vert`: `uniform mat4 world` becomes `// @instanced layout(location=2) in mat4 iWorld`
  - Per-instance overrides (opacity, color mix) that currently go through `EntityParameters` → uniform also become instance attributes if they vary per instance, or stay as uniforms if they're global to the draw call
- `default.vert`: same pattern if it uses a world matrix uniform
- `lineStrip.vert`: evaluate if still needed (ghost previews), migrate or remove
- `terrain.vert`: no per-instance data (single draw), add a dummy instance or treat as special case
- 2D shaders (`texturedRectangle.vert`, `msdfText.vert`): already `@instanced`, no change needed

**Validation:** Asset pipeline generates both `Vertex` and `Instance` for every shader. Project builds. Rendering still uses old paths — shaders are forwards-compatible.

### Step 3: Unified renderer + consumer migration

Replace `RenderingManager2D` + `RenderingManager3D` with a single `RenderingManager`.

**Engine changes:**
- New `RenderingManager` with `RegisterGeometry`, `RegisterGroup`, `SetInstances`, `Render`
- Single render path: set blend/depth state, bind shader, bind VAO, `DrawElementsInstanced`
- Draw ordering via `BlendState` flag (e.g. `OrderMode.None` vs `OrderMode.BackToFront`)
- Delete `RenderingManager2D`, `RenderingManager3D`, `OpenGLQuadRenderingManager`
- Delete per-instance uniform loop and `SetInstanceWorld`/`SetInstanceParameters`

**Consumer migrations:**
- `BuildingRenderingService`: `RegisterGeometry<Building.Vertex>` + `RegisterGroup<Building.Instance>` + `SetInstances` on add/remove
- `TrackRenderingService`: already close to target pattern, switch from raw `OpenGLInstancedBufferManager` to `RegisterGroup<Track.Instance>`
- `TrackGhostRenderingService`: becomes another instance group (possibly with its own ghost shader, or same shader with different blend state)
- `GuiRectangleRenderingService`: `RegisterGeometry` with unit quad + `RegisterGroup<TexturedRectangle.Instance>`
- `VehicleRenderingService`, `JunctionSignalRenderingService`, etc.: same pattern

**Deletions:**
- `RenderingManager2D`, `RenderingManager3D`
- `OpenGLQuadRenderingManager`
- `TrackTemplateMeshService.TrackVertex` (already deleted in step 1)
- Per-instance VAO/VBO creation in 2D path
- `IShaderParameters` / `EntityParameters` for per-instance uniform overrides (replaced by instance buffer data)

**Validation:** All rendering goes through unified manager. Integration test screenshot matches.

## Open Questions

- **Terrain shader** has no per-instance data and derives geometry from `gl_VertexID`. It could be treated as a single instance with no instance attributes, or remain a special case with `DrawArrays` instead of `DrawArraysInstanced`. Either works — `DrawArraysInstanced(..., 1)` is functionally identical.
- **Per-instance uniform overrides** (`EntityParameters`) are currently used for ghost building opacity. In the always-instanced model, this would become an instance attribute (e.g. `in float iOpacity`). This is more flexible (GPU-side, no CPU uniform restore) but means the shader must declare all per-instance variation upfront.
- **Draw order for transparency.** 2D currently sorts by explicit depth. The unified renderer needs an ordering mechanism for transparent groups. A `BackToFront` sort mode on the group (sorting by a designated field in the instance data) would handle both 2D UI and future transparent 3D objects.
